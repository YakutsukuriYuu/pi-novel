# 长篇连续性

## 资料职责

- lore/characters：初始与长期人物设定，包含作者层面的秘密。
- lore/relationships：初始关系；动态变化放 continuity/relationships。
- continuity/states：一人物一时点的状态快照，记录地点、伤势、资源、知识与误解。
- continuity/events：故事内时间和因果，不把叙述章节顺序当故事时间。
- continuity/threads：伏笔/支线计划和有来源的实际推进。
- summary：逐章发生事实，不能替代正文。

## 来源

派生记录用 sources 保存实际阅读的正文路径和精确 revision。refs 用稳定 ID 连接人物、地点、关系等。关系认识、人物知识都可能不对称。

来源是草稿时，记录不得当作正式事实。来源过期时返回正文核对，保留疑点，不只刷新哈希。

## 改前文

1. novel_check 找过期来源，catalog 检索相关实体和事件。
2. 标出直接依赖，以及可能受影响的后续情节。
3. 先提出修订方案，再按用户授权修改；不要无界地修整本小说。
4. 复核相关摘要、状态、关系和伏笔。

插件不会推断所有语义依赖。未显式引用的矛盾仍需阅读和判断。角色未来状态、未发生的计划、作者秘密不能无标记地混入当前场景。

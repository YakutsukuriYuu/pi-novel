# 长篇连续性

## 各类资料的职责

| 目录 | 职责 |
| --- | --- |
| `人物/` | 初始与长期设定，包含作者层面的秘密 |
| `人物/关系/` | **初始**关系 |
| `情感线/` | 跨全书的关系**轨迹**：从哪到哪，拐点在哪 |
| `当前状态/人物/` | 一人物一时的状态快照：地点、伤势、资源、知识与误解 |
| `当前状态/关系/` | 某一章结束时的关系切片 |
| `时间线/` | 客观事件编年，不把叙述顺序当故事时间 |
| `伏笔/` | 埋设与回收的账 |
| `摘要` | 逐章发生的事实，不能替代正文 |

**情感线 ≠ 当前状态/关系**：前者是设计（长期走向），后者是事实（某一刻的样子）。
**时间线 ≠ 当前状态**：前者是客观发生了什么，后者是人物以为发生了什么。这个差值就是叙事张力。

## 来源

派生记录（摘要、状态、事件、关系变化、审稿）必须用 `sources` 记录**稳定编号 + 精确 revision**。

- 编号而不是路径：作者会在 Obsidian 里重命名文件。
- revision 是文件完整字节的哈希：**哪怕只改一个标点，来源就过期**。

来源还是草稿时，记录不能当作正式事实。来源过期时回到正文核对，保留疑点，
**不要只刷新哈希假装没事**。

人读的来源写进正文：`依据：[[章节/0001-雨夜/正文]]`。

## 改前文

1. `novel_check` 找过期来源；`catalog` 检索相关实体和事件。
2. 标出直接依赖，以及可能受影响的后续情节。
3. **先提出修订方案**，再按作者授权修改；不要无界地修整本小说。
4. 复核相关的摘要、状态、关系和伏笔。

插件不会推断所有语义依赖。没有显式引用的矛盾仍然需要阅读和判断。
角色未来状态、未发生的计划、作者秘密，都不能无标记地混进当前场景。

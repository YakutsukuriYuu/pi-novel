# 审稿

默认不修改正文。先确认范围，不要把局部审稿扩大成全书重写。

读取被审正文及相关前文、`规则/`、`设定/文风.md`、人物卡与章节方案，
创建 `审稿/` 记录，`sources` 引用**实际阅读的正文编号和版本**。报告结构：

- **严重度**：阻断 / 重要 / 建议
- **位置**：章节路径、场景，或可定位的短引文
- **证据**：与哪条已确认设定或已发生事件冲突
- **影响**：为什么损害理解、情节或人物
- **建议**：最小可行修改，必要时给两个方向

检查：因果、人物动机、知识边界、时空连续性、世界规则、物品、关系、伏笔、节奏、视角、文风。

不要把个人口味当客观错误。区分硬矛盾、待作者决定、风格建议。
避免空泛赞美，也不要为凑数捏造问题。证据不足就标记未验证。

报告只代表当前模型的审查，**不要声称经过了独立的多次审核**。
`novel_check` 通过也不代表故事正确。

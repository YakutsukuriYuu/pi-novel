# 写入保护与恢复

## 正常写入

1. 获取项目内 `.novel/lock/` 互斥锁（owner.md 记录 PID 和启动时间）。
2. 校验预期版本与受管路径。
3. 先在 `.novel/pending/` 保存 pending 事务 Markdown，包含所有 before/after 快照。
4. 每个文件使用临时 Markdown + rename 替换。
5. 将事务标记 committed，移动到 `.novel/transactions/` 归档，释放写锁。

Pi 工具还通过宿主队列序列化同一项目操作。多 Pi 进程竞争时，一个写入者获取锁，其他写入者报告冲突，而不是同时覆盖。

跨文件更新不是文件系统原子事务：中断可能有部分文件已写入。pending 记录会阻止后续受管写入，直到显式恢复。

## 回滚最近一次修改

```text
/novel history
/novel recover 时间戳-UUID
```

先检查对应 `.novel/transactions/时间戳-UUID.md`，未完成事务位于 `.novel/pending/`，再确认回滚。恢复前逐个检查当前文件是否还是该事务的结果；有后续或外部改动会拒绝覆盖。

要恢复更早版本，应从最近相关修改向前回滚，或者把旧快照另存为提案并人工合并。不要用 force/reset 绕过冲突。

恢复过程本身也先写 pending 标记，可以在恢复中断后再次执行。新建文件回滚会删除该事务创建且没有后续变更的文件；旧内容恢复为精确 before 快照。

## 进程崩溃后锁未释放

插件**不会自动抢占或按时间猜测锁已过期**。

1. 停止所有正在操作这本书的 Pi 和其他写入进程。
2. 复制整个小说文件夹到安全位置，包含 `.novel/`。
3. 阅读 `.novel/lock/owner.md`，确认记录的进程不再写书；PID 可能被系统复用，不能只看进程号就判断。
4. 仅在确认没有写入者后，手动删除该书的 `.novel/lock/` 目录，不要删除 transactions。
5. 重新打开项目，运行 check/history，对 pending 事务执行 recover。
6. 若报告 Recovery conflict，先保存当前文件，查看 before/after 与作者修改，手动合并；不要删除日志来伪装成功。

隐藏的 `.<文件名>.<UUID>.md` 为原子写临时文件；崩溃后可能残留。它们不作为正文或事务索引。先完整备份，再在确定无进程运行时清理。

## 初始化中断

初始化只操作新目录或空目录，`.novel/project.md` 标记最后写入。中断前的模板保存在 `.novel/setup/` 或已放到最终位置。

如果尚无 project.md，目录不会被当成完整项目。先备份，检查是否有作者内容；最安全的做法是换一个全新空目录重新初始化，再手动迁入有效 Markdown，而不是强制重跑覆盖旧目录。

## 外部编辑

可以在任意 Markdown 编辑器阅读和编辑小说。避免和模型同时保存同一个文件。插件每次读取磁盘，使用精确 revision 防止已观察到的过时写入。

对 accepted/published/confirmed 文件的正文做外部修改，check 会报告正文校验值不符；接受章节的改稿也会阻止导出与发布。请 reopen 后审核修改、重建摘要，再 accept/confirm。

## 安全边界

这是本地工作流保护，不是对恶意程序的安全隔离。用户 shell、外部编辑器及其他插件自身的文件访问不受 OS 级限制。内置只读工具名假定未被替换成恶意写工具。插件防路径穿越、拒绝受管路径中的符号链接、硬链接和特殊文件，但不承诺抵御并发恶意替换目录的攻击。

事务快照在同一磁盘，不能代替异地备份。文件句柄刷新不等于全文件系统断电恢复保证。请定期备份整本小说及其历史。
